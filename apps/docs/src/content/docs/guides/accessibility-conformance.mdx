This page reports Focsd's status against the [Web Content Accessibility Guidelines (WCAG) 2.2](https://www.w3.org/TR/WCAG22/), level AA, in the style of a conformance report. It covers the components, not your application: a page built with accessible components can still fail WCAG (see [What stays your job](/foundations/accessibility/#what-stays-your-job)).

<Aside type="caution" title="Status: manual screen reader pass and text spacing test pending">
Every result below is backed by automated tests, except where it is marked pending. We have not yet done a manual pass with NVDA, JAWS, VoiceOver (macOS and iOS) and TalkBack, so we do not claim full conformance for criteria that depend on how screen readers announce content (marked "Supports, pending manual check").
</Aside>

## How it is tested

| What | How |
|---|---|
| Rules | [axe-core](https://github.com/dequelabs/axe-core) with the WCAG 2.0, 2.1 and 2.2 A and AA rule sets |
| Browsers | Chromium, Firefox and WebKit (Playwright), on every change |
| Themes | Light, dark and high contrast, including every open overlay, menu and popover |
| Keyboard | A scripted keyboard test for every component, following the [ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) patterns |
| Accessible names | Checked through the browser's accessibility tree for every control, label forwarding and translation |
| Reflow and spacing | Blocks and selected components (fields, the table, the swatch picker) at 320 CSS pixels wide. A test that applies WCAG text spacing to every shadow root is planned, not yet in place |
| Contrast | Text and non-text token pairs checked in all three themes |
| Layout stability | Docs pages measured for layout shift on cold, CPU-throttled loads |

## Criteria

Conformance levels follow the VPAT (Voluntary Product Accessibility Template) convention: **Supports**, **Partially supports**, **Does not support**, **Not applicable**.

| Criterion | Level | Status | Notes |

| 1.3.1 Info and relationships | A | Supports | Labels, hints and errors share a shadow tree with their control; roles follow the ARIA Authoring Practices. |
| 1.3.2 Meaningful sequence | A | Supports | Reading order equals visual order, including right-to-left. |
| 1.3.3 Sensory characteristics | A | Supports | No instructions rely on shape or position alone. |
| 1.3.4 Orientation | AA | Supports | No orientation lock. |
| 1.3.5 Identify input purpose | AA | Partially supports | `autocomplete` works on text, password, combobox, date and code fields. `focsd-select` and `focsd-time-field` cannot be autofilled by browsers; use `focsd-combobox` or a native control for personal data. |
| 1.4.1 Use of color | A | Supports | Links are underlined; status uses words and icons; disabled controls are hatched. |
| 1.4.3 Contrast (minimum) | AA | Supports | Tested in all three themes. Your brand colors replace ours: test them. |

## Known limitations

- **Shadow DOM and ID references.** A `<label for>` or `aria-labelledby` outside a component cannot point inside it. Components forward the host's `aria-label`, `aria-labelledby` and `aria-describedby` as text; when browsers ship [Reference Target](https://github.com/WICG/webcomponents/blob/gh-pages/proposals/reference-target-explainer.md), we will adopt it.
- **`readonly` on choice controls.** HTML skips validation for any custom form control with a `readonly` attribute, so `focsd-select required readonly` submits empty. Don't use `readonly` on select, checkbox, switch, radio group or slider.
- **`list` (datalist)** is not supported; use `focsd-combobox`.
- **Translations.** Only English ships today. Other languages need a [translation table](/foundations/localization/).

## Reporting a problem

Found a barrier? [Open an issue](https://github.com/SunTribe1/focsd/issues/new) with the component, browser, assistive technology and what you expected. We treat accessibility bugs as the highest priority.
